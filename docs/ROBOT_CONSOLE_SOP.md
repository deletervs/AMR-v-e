# 机器人监控与基础控制台：开发练习 SOP

日期：2026-10-08。状态：需求与开发建议，尚未实现或部署。

用户目标：PC/手机使用完整仪表盘；调用相机、雷达与底盘；虚拟键位和 XSS 手柄操控；开关机。首版范围明确包括里程计、CPU/内存/温度和日志。XSS 暂按 Xbox Series 手柄理解，型号与连接方式待核实。

使用场景：操控通常在机器人旁边，仪表盘需要远程查看。网络方案仍在讨论，不把“局域网或远程”当作只能二选一。

## 1. 范围与已有证据

参考 [项目上下文](PROJECT_CONTEXT.md)、[源码地图](SOURCE_MAP.md)、[机器人源码地图](ROBOT_SOURCE_MAP.md)、[C++ 开发流程](CPP_DEVELOPMENT_WORKFLOW.md)、[自主修复目标](SELF_REPAIR_VISION.md)。它们记录检查快照，不代表当前运行状态。

- 机器人记录为 Jetson Nano、Ubuntu 18.04、ROS1/Melodic；学校服务器为 x86_64。服务器离线构建通过后，真实接入还要验证机器人 ARM 构建与运行。
- 厂商源码的 /handsfree/robot_state 有电压、电量、CPU 温度/使用率；发布频率、单位、量程、电量标定与实时数据需要核验。
- 相机、雷达、IMU、超声和底盘接口已有源码。碰撞、充电、急停等内部字段部分未发布，不能直接承诺真实显示。
- 厂商控制器默认 0.5 秒速度超时，尚未现场验证物理停止；自有 agent 缺独立命令有效期和完整退出停止契约。已有部分避障示例没有实际限速。
- [Gemini 官方手册](https://docs.taobotics.com/docs/gemini/)说明物理电源开关；当前没有证据证明机器人已支持远程整机开机。

第一版产品范围完整，但按多个小里程碑交付。不可用数据明确显示未知/未支持，不能用假值冒充真实值。

## 2. 联网与上线方案

推荐目标结构：本地操控 + 远程监控 + 独立设备管理。共用页面和数据模型，在后端执行不同权限。

| 场景 | 访问方式 | 建议权限与行为 |
| --- | --- | --- |
| 机器人旁边 | PC/手机与机器人处于可互通的局域网，访问本地服务 | 完整状态、虚拟键位、手柄；操控需要本地使能与短期控制权 |
| 外出查看 | 私人 VPN，或登录云端仪表盘 | 远程只读状态、图像/雷达预览、历史日志；遥测断开标记过期 |
| 开关机/重启 | 独立的设备管理入口 | 和查看、运动权限分别授予；是否允许远程管理另定 |
| 互联网断开 | 本地服务继续运行 | 本地操控与机器人停止保护不依赖云端在线 |
| 机器人离线/关机 | 云端或常在线网关仍可打开 | 显示最后在线时间与历史记录，不能继续显示为实时健康 |

“旁边”是使用场景，不由 IP 地址自动证明。仅连上局域网或 VPN 不自动获得运动权限。本机授权/使能与机器人端控制会话要独立实现；云端首版不提供速度命令入口。

可选部署路径：

| 路线 | 使用体验 | 工程工作与限制 |
| --- | --- | --- |
| 局域网服务 | 同网 PC/手机打开网页 | 最先验证；校园 Wi-Fi 可能有客户端隔离，需要实测互通 |
| 局域网 + 私人 VPN | 外出后先连接 VPN，再看同一仪表盘 | 适合个人早期上线；需验证旧 OS/ARM 客户端兼容、校园出网和手机网络 |
| 域名 + 认证隧道 | 浏览器登录访问机器人旁的服务 | 隧道不是遥测存储；本地服务下线时不能提供实时数据 |
| 云端仪表盘 + 遥测上报 | 打开域名登录，查看实时及历史状态 | 练习后端、认证、数据库、部署与运维；机器人主动向云端上报，云端不介入首版运动控制 |

[Tailscale 官方说明](https://tailscale.com/docs/concepts/what-is-tailscale)介绍私有网络及免端口转发的连接；[连接类型说明](https://tailscale.com/docs/reference/connection-types)说明直连失败时可能中继，吞吐与延迟需测量。[Cloudflare Tunnel 官方说明](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/)介绍主动出站隧道、不要求本地公网 IP 的访问方式。这些是候选，未安装或证明在当前校园网络可用。

建议先做好离线与局域网闭环，再做远程联网小验证；个人自用可先选择 VPN。若希望“打开域名就能看”、保存历史或给他人展示，则把云端仪表盘作为后续上线目标。主方案确定前不要求购买服务器或域名。

学校服务器先承担现有源码保存、独立构建、测试及后续计算职责；其 SSH 已连通不等于可作为公网网站服务器。云端地址、出站网络和访问政策需单独核实。

## 3. 完整仪表盘的属性

| 分组 | 属性 | 数据契约 |
| --- | --- | --- |
| 连接 | 机器人/网关在线、最后更新时间、延迟 | socket 连通和数据新鲜度分别显示 |
| 能源 | 电压、电量、充电状态 | 电压 V；电量算法需核验；未发布的充电状态显示未知 |
| 底盘 | 目标与实际线速度/角速度、运动使能 | m/s、rad/s；下发值不当作实际速度 |
| 控制与停止 | 控制者、输入来源、授权期限、停止原因、硬件急停反馈 | 软件停止与硬件急停区分；未接反馈不显示“正常” |
| 相机 | RGB 画面、分辨率、有效帧率、帧时间；之后可加深度 | 冻结帧显示过期；主链当前只用 RGB |
| 雷达 | 二维扫描、分区最近有效距离、有效频率 | 单位 m、标注坐标系；无有效量测不等于无障碍 |
| 里程计与 IMU | x/y/yaw、姿态、里程/运行时长 | 标注局部坐标系；里程计不当作全局准确位置 |
| 计算资源 | CPU、内存、温度、磁盘 | 标明来自 Jetson 还是底层控制器 |
| 服务健康 | 进程状态、组件心跳、数据年龄 | 进程活着但数据冻结仍属于异常 |
| 日志与版本 | 事件、命令结果、故障原因、源码/配置版本 | 记录来源、request_id、时间、结果，支持复现与回退 |

每项属性定义：值、单位、来源、采样时间、接收时间、序号/启动代次、质量状态及过期规则。建议质量状态为 unknown、valid、stale、fault、unsupported。

电池、运动、视频分别设置更新与过期阈值。先测真实发布频率与链路延迟再定指标；不要用网页刷新时间掩盖传感器没有新数据。

远程先上报小型状态与事件；相机和雷达采用按需预览、限帧率和限带宽。视频通道与控制通道隔离，图像拥塞不应延长运动命令有效期。历史记录先用简单存储，规模需要时再引入时序数据库。

## 4. 页面与模块

建议响应式 Web 页面，PC 和手机共用。前端用 HTML/CSS 与 JavaScript/TypeScript，C++ 练习集中在状态、控制契约和适配器。

页面分四个区域：总览仪表盘、相机/雷达、遥控、设备管理。日志可先做独立面板。

逻辑结构：

    本地 PC / 手机 -> 本地网关 -> 机器人本机安全与控制仲裁 -> ROS1 / 设备
                                      |
                               状态与事件上报
                                      v
    远程 PC / 手机 -> 登录 -> 远程只读仪表盘 / 历史记录

初期可以共进程，不必拆微服务。机器人本机的命令超时和停止保护不依赖浏览器、网关或学校服务器存活。

接口先设计三份契约：

- RobotState：属性、单位、质量、时间、数据年龄。
- Command：目标、动作、来源、会话/授权代次、序号、有效期、request_id。
- Capabilities：支持动作、前置条件、可用状态及不可用原因。

先 mock 适配器，后 ROS1 适配器。现有 Python 可以过渡复用；新 C++ 核心先不依赖视觉模型。HTTP 查询/低频管理动作与 WebSocket 状态/短期输入即可起步，具体库在需要时核对版本与目标平台。

命令结果区分接收、拒绝、执行中、经反馈验证成功、失败和结果未知。发送成功不等于物理执行成功。设备管理动作通过 request_id 去重。

相机/雷达“开关”区分：预览订阅、驱动服务启停、物理供电。首版先做预览订阅，再接已核实的服务能力；运动所依赖的传感器停用要受前置条件限制。

## 5. 两种遥控的统一契约

虚拟键位：按住前后左右，松开停止；手机触摸与 PC 鼠标分别验证。

XSS 手柄：暂建议左摇杆前后给线速度、左右给转向，按住肩键使能，独立按钮软件停止。设置死区、回中检查和速度限制。

浏览器可用 [Gamepad API](https://www.w3.org/TR/gamepad/)读取轴与按钮；映射、识别与浏览器行为需要实测。未知映射先校准；PC USB/蓝牙和手机蓝牙分别验收。使用 HTTPS/WSS，并验证目标浏览器的实际访问条件。

共同规则：

- 默认禁止运动；控制权、输入回中与主动使能都是明确条件。
- 同时只有一个有效运动控制者；接管先停止并使旧授权失效，停止请求不被普通运动租约挡住。
- 松开使能、失焦/切后台、锁屏、手柄断开、数据过期或断联时，停止续约并请求停止；机器人本机独立超时兜底。
- 机器人本机用单调时钟计时，拒绝过期会话、重复/乱序和旧启动代次命令。端到端有效期要拒绝被网络延迟的旧运动，不能仅在到达后重新开始 TTL 就当作新鲜输入。
- 检查有限数值、单位、速度/加速度限制和依赖的传感器健康；示例阈值不能直接用于现场。
- 软件停止锁存；重连、重启、修复或开机后不自动恢复旧速度与旧使能。
- 接真实底盘前核验旧手势、导航、厂商遥控等发布者的路由和仲裁，避免争抢最终速度话题。
- 网页停止依赖通信和软件；独立硬件急停能力另外核实。

先通过停止、陈旧输入、掉线、旧包和双客户端用例，再测正常运动。没有接入并验证避障就不宣称安全遥控具备避障。

## 6. 开关机与重启

| 能力 | 前提与第一版处理 |
| --- | --- |
| 启停相机/雷达/机器人服务 | 核实服务、依赖及权限；先 mock，再以进程状态和新数据确认成功 |
| 运动使能/禁止 | 属于控制状态；物理电机使能另核实，不与主机电源混用 |
| Jetson 正常关机/重启 | OS 接口、有限权限和停止前置条件；重启后回到禁止运动 |
| 主机已关机但整机仍供电时启动主机 | 需要核实主板电源键/专用接口，当前未证明支持 |
| 整机断电后的远程开机 | 需要常供电且可联网的电源控制器/专用硬件；没有支持就显示不可用，并保留 mock 演示和物理开关 |
| 整机断电 | 需要独立电源控制和正确动作顺序；OS 关机不代表底盘/MCU 断电 |

彻底断电的机器人无法靠自己运行的服务接收开机指令。Wake-on-LAN 只在硬件、固件与待机供电支持时可作为候选，当前不能承诺 Jetson 或整机支持。电源硬件与电气规格作为独立可行性任务，不在本计划中指定改线。

正常关机建议流程：确认目标设备 -> 撤销运动授权并拒绝新运动 -> 停止并核验可用实际反馈 -> 停止任务/保存必要数据 -> 正常 OS 关机 -> 记录请求与后续可验证结果。

无可靠实际速度反馈时不能将“已发送零速度”当作“停止已确认”；真实关机前确定验证方法或保持动作不可用。掉线可能由断网、崩溃或关机引起，缺外部反馈时记录结果未知，不宣布整机已断电。

关机、重启和开机属于独立设备管理权限。前端只提交白名单动作，不提供任意 shell 或 SSH 凭据。Linux [logind 接口说明](https://wiki.freedesktop.org/www/Software/systemd/logind/)介绍关机/重启及支持与权限查询；适配时核对机器人安装版本。配置真实权限属于后续部署事项，本次不修改。

## 7. 轻量工程 SOP

| 步骤 | 产物 | 通过条件与练习能力 |
| --- | --- | --- |
| 需求分析 | 一页需求、属性选择、场景和验收句子 | 会写范围、优先级、成功与失败条件 |
| 可行性核验 | 数据源/能力表、证据、未知项 | 区分源码存在、设备枚举、运行数据和现场验证 |
| 设计评审 | 页面草图、状态机、接口和网络方案 | 单位、时间、未知状态、控制权、停止、电源边界明确 |
| 拆任务 | 一个目标一张卡、每卡有验收用例 | 一至两个学习时段能检查进展，大任务继续拆 |
| 实现 | 你写小 C++ 模块和必要测试 | 能解释类型、边界、生命周期与逻辑；AI 解释和审查 |
| 验证与代码评审 | 离线证据、目标平台日志、diff、未验证项 | 测试真实运行，日志对应确切版本 |
| 发布与回顾 | 已批准的范围、回退、问题记录 | 可回退到模拟/只读或已知版本，复盘失败与遗漏 |

一张任务卡模板：目标；输入/输出；不确定项；验收用例；实现；验证证据；审查意见；是否完成。

每个功能循环：定契约 -> 你写主体 -> AI 审查 -> 测试 -> diff 评审 -> 按授权提交/接入 -> 记录结果。

Git 与构建沿用 [既有流程](CPP_DEVELOPMENT_WORKFLOW.md)：PC 为唯一编辑来源；独立服务器挂载 checkout 测试相同 commit；保护原 Python 与忽略快照。不自动 commit/push，不在服务器维护第二套独立编辑代码。

## 8. 交付顺序

| 里程碑 | 演示与验收 |
| --- | --- |
| M0 需求与接口 | 完整属性表、网络候选、页面草图、命令及电源边界 |
| M1 模拟完整仪表盘 | 所选属性有 mock 数据、未知/过期显示和日志；PC/手机页面可用 |
| M2 真实只读监控 | 逐项核验真实数据，接相机/雷达和资源指标；真实缺项明确标注 |
| M3 离线遥控 | 虚拟键位/手柄控制假机器人，断联、切后台、双客户端、旧包用例通过 |
| M4 本地真实遥控 | 明确授权后验证机器人本机保护、ARM 构建、实测停止和有限运动 |
| M5 设备与电源 | 先 mock 全流程，再按已核实能力和独立授权接服务与开关机 |
| M6 远程上线 | VPN 或云端方案；认证、只读权限、历史记录、遥测掉线、互联网断开本地可用 |
| M7 整体验收 | PC/目标手机/手柄场景、版本记录、回退演示、能力缺口 |

M1–M3 可以形成首个不依赖真实运动的演示。M4–M6 中的真实部署、运动、电源操作分别按明确请求进入。总工期取决于 C++/前端基础、网络和电源能力，先按一至两个小时一个学习时段迭代，不承诺固定天数。

## 9. 第一份 C++ 作业

目标：状态类型与新鲜度纯逻辑，不依赖 ROS、网络或实体机器人。

1. 写 DataQuality 枚举：未知、有效、陈旧、故障、未支持。
2. 写首批 RobotState 字段：连接、可选电压、目标/实际速度、运动使能、来源和停止原因；其余仪表盘字段逐卡加入。
3. 定义每项数据的时间与新鲜度规则，不能一个网页刷新时间替代所有传感器时间。
4. 用可注入单调时间写 is_stale，先明确等于阈值的行为。
5. 验证正常更新、等于/超过阈值、缺失数据、启动代次变化。

学习 struct、enum class、std::optional、const、单调时钟和边界测试。先由你写接口和用例，AI 评审后再实现。后续卡片：假状态生产者 -> JSON 样例 -> 网页展示 -> 数据流。

## 10. 与自主修复衔接

状态质量、心跳、依赖、故障原因、动作结果和版本可以供未来独立维护模块使用。状态页和重启按钮不等于已实现自主修复。

后续离线修复演示遵循 [既定目标与验收](SELF_REPAIR_VISION.md)：自主发现 mock 故障、有限诊断与修复、独立验证和有界失败；修复不恢复旧运动授权。软件操作、已登记硬件及未预接入工具目标保留，真实物理维修与远程电源仍有能力缺口。

## 11. 外部模型控制扩展

2026-10-10 用户新增外部大模型直接操控目标，见 [接口与验收路线](EXTERNAL_LLM_CONTROL.md)。模型可下发限时底盘动作及已实现技能，并根据状态与动作反馈继续决策。
复用本 SOP 的 RobotState、Command、Capabilities 和单一控制权仲裁，不增加绕过本机安全层的速度发布者。
