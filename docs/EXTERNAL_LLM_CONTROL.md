# 外部大模型直接控制机器人

记录日期：2026-10-10。状态：新增功能目标、接口草案与验收路线；尚未实现或接入真实机器人。

## 目标与直接控制的含义

外部大模型可以读取机器人与环境信息，下发具体动作或技能调用，获得执行反馈，再决定下一步动作，形成观察、决策、执行、反馈闭环。
在已经授权的运行会话内，动作不需要人逐条转写或点击执行。既支持高层任务，也保留直接下发底盘线速度/角速度及持续时间的入口，不把功能缩成只给建议。

“直接控制”不等于云端拥有机器人 root、任意发布 ROS 速度话题或移除安全保护。模型决定动作，本机控制器检查并执行；不符合条件的命令明确拒绝。
外部模型提供商暂不指定，后续按可用接口、网络、视觉能力、成本和隐私要求选择；现有聊天客户端可用不代表机器人 API 接入已完成。

## 接入结构

```text
机器人传感器 / RobotState / Capabilities
  -> 本地网关 -> PC 或服务器上的模型适配器 -> 外部模型接口
  <- 执行反馈 <- 本机控制与设备适配器 <- 命令校验与控制权仲裁
                                             ^
                                      模型结构化动作请求
```

模型适配器主动调用外部模型，并将模型动作请求送入受控网关；外部模型不需要直接访问校园内网或持有 SSH 私钥。
实际运行位置由网络可达性和部署授权决定，最小演示可把适配器和假机器人都放在 PC。学校服务器不能访问某个模型服务时，可由 PC 调用，复用已授权的内网连接。
这不依赖在远程 VS Code 上安装 AI 插件；正式接入仍需确认模型接口、凭据、出网和数据上传许可。

先复用 [控制台 SOP](ROBOT_CONSOLE_SOP.md) 的 RobotState、Command、Capabilities 和单一最终运动出口，不让模型成为绕过仲裁的另一个 cmd_vel 发布者。
现有 Python SSH agent 只能作为后续适配参考，不直接把它当作已具备认证、会话和完整安全契约的模型控制服务。

## 拟议能力接口

下表是接口设计，不是已经可调用的 API。

| 接口 | 输入/输出与用途 | 权限 |
| --- | --- | --- |
| `get_robot_state` | 带质量、数据年龄、启动代次、控制者和停止原因的状态 | 只读 |
| `get_sensor_snapshot` | 受限帧率/带宽的相机或雷达快照，保留坐标系与采集时间 | 传感器读取与外发数据权限 |
| `get_capabilities` | 当前支持的动作、前置条件、参数单位与不可用原因 | 只读 |
| `set_velocity` | linear_x、angular_z、duration_ms；限时底盘动作 | 有效运动会话与使能 |
| `stop` | 软件停止并撤销/锁存运动使能，返回可核验状态 | 已认证来源可请求；不被普通运动租约挡住 |
| `invoke_skill` | 已登记技能名及结构化参数；不能调用未实现技能 | 按技能分别授权 |
| `get_command_result` | 查询 request_id 的状态、反馈、失败原因或结果未知 | 所属会话的结果读取 |
| `cancel_command` | 取消自身在执行的动作；需要停止时进入停止流程 | 对应会话/任务权限 |

单位固定为 m/s、rad/s、ms；拒绝非有限数值、额外未知动作和越界参数。限速、加速度与时长上限由机器人侧策略决定，不能相信模型自报“安全”。
移动、转向先表达为限时速度动作，不在缺少已验证里程计/控制反馈时承诺准确走到某个距离或角度。
导航、跟随、指向位置等技能只有实际实现且通过验收后才可列为 available。当前 point 计划没有实际运动执行，不能在工具清单中冒充已实现导航。
关机、重启、硬件复位和维修动作属于独立权限，首个模型控制雏形默认不开放。

## 命令与反馈契约

复用统一 Command，并明确 request_id、session_id、授权代次、启动代次、命令序号、观察引用、有效期、动作和参数。
来源与权限由已认证的适配器和网关确定，不由模型填写一个 external_llm 字符串就获得身份。
模型只能使用已颁发的会话，不能自行授予运动权限、生成新授权或调整安全规则。

模型思考和网络传输耗时必须计入新鲜度。拟议做法是使用机器人发出的观察/授权引用及本机单调时钟截止条件，接收时同时检查输入数据和命令期限。
不能让经过长时间延迟的旧动作到达后重新开始 TTL，就把它当作新命令；具体端到端计时协议在实现前单独测试。
动作到期后机器人停止，不靠外部模型记得调用 stop；模型服务超时或断网时，本机保护仍要生效。

结果区分 accepted、rejected、running、verified_succeeded、failed、cancelled、expired、unknown，并说明验证来源。
发送成功或 ROS 发布成功不是物理动作成功。反馈缺失时保留 unknown；不能让模型根据自己期待的结果补写成功。
重复 request_id 不再次执行；乱序、旧启动代次和旧会话命令拒绝。结果未知时先查询/停止，不盲目重放运动或设备管理动作。

## 与其他控制来源协调

- 手柄、虚拟键位、手势、导航、外部模型和维修模块共用控制权仲裁，同一时刻只有一个最终运动控制者。
- 独立硬件急停和本机安全停止不依赖模型；人工停止优先于普通动作，模型不能解除停止锁存。
- 人体/人工接管时先停止并使旧模型会话失效；旧模型响应即使稍后返回，也不能恢复运动。
- 修复模式隔离受影响任务并按独立授权调用修复能力；模型控制权限不自动包含自主维修权限。
- 重连、重启和修复成功不恢复旧速度与旧授权。恢复服务与允许运动是不同状态。

默认只读或 mock；真实运动会话需要单独明确授权及本机条件验证。这不要求每个正常动作都由人批准，但需要预先限定可自动执行的范围。
既有 [控制台 SOP](ROBOT_CONSOLE_SOP.md) 的云端首版仍只读；未来外部模型控制是单独受控入口，不把远程仪表盘直接改成公网运动接口。
传给模型的图像、状态与日志先最小化和过滤，密钥不进仓库、提示词或机器人观察内容；工具返回文本作为数据，不允许其改变权限或停止规则。

## 第一版雏形及验收

沿用当前 [M1-001 状态模型任务](tasks/M1-001-state-model.md)，不插队替用户生成完整控制程序。
先完成 RobotState、统一 Command、假机器人和仲裁，再进行以下独立里程碑：

| 里程碑 | 演示 | 完成条件 |
| --- | --- | --- |
| LLM-1 离线工具执行链 | 回放模拟模型的结构化请求，控制假机器人 | 状态查询、限时移动/转向、停止、结果查询；过期、非法、重复、抢占用例通过；不宣称真实模型已接入 |
| LLM-2 外部模型闭环 | 一个实际模型接口读取假状态、选动作、收到反馈并调整 | 保存真实模型请求与动作/结果关联；模型错误、超时或断网时假机器人停止；没有人工逐条转写动作 |
| LLM-3 真实只读接入 | 模型读取授权范围内的真实数据，仍禁止运动 | 数据质量、外发范围、认证和网络核验；缺项显示 unknown/unsupported |
| LLM-4 有限真实动作 | 单独授权后，在约定场地做有限动作 | 对应机器人平台构建通过；独立停止、传感器前置条件、控制权和现场反馈验收先通过 |

负向测试至少包括：畸形请求、NaN/Infinity、过大速度/时长、未知技能、陈旧画面、乱序、重复请求、模型返回延迟、断联、双来源争抢及人工停止后旧响应返回。
代码由用户分小模块实现：C++ 练习集中于命令类型、验证、仲裁、生命周期、状态机与反馈；提供商协议适配可先采用小型过渡适配器，再决定迁移范围。
每次测试记录准确版本、动作/状态变化、拒绝原因和实际覆盖项。接口设计、假请求回放、真实模型闭环和真实运动是四种不同证据。

## 距离完整功能的缺口

仍需实现统一命令入口、鉴权和控制会话、参数与有效期验证、仲裁、模型适配器、可靠状态/传感器读取、动作反馈与故障测试。
物理执行还需要机器人平台构建、健康条件、现场停止验证与能力适配；不能仅凭厂商源码存在超时逻辑就宣称现场验证完成。
自然语言目标落到环境对象或世界坐标，还缺语义感知、标定、空间状态和相应技能；单靠模型看图与输出速度不代表可靠导航或意图理解。

本次只补充目标、接口与路线，没有调用外部模型、外发数据、连接真实机器人、修改部署、执行运动、提交或推送。
