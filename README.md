# RS：移动机器人多端交互与控制系统

基于 Taobotics Gemini 的二次开发；保留原厂固件、驱动与系统组件。

## 开发目标

1. **C++ 与 AI 协作开发训练**：亲自实现核心模块，掌握设计、编码、调试、测试及 Git/PR 开发流程。
2. **人机融合与外部肢体**：结合人的动作、环境和任务上下文理解意图，让机器人作为人的外部肢体完成任务。
3. **外部大模型直接操控**：通过统一接口让模型读取状态、下发具体动作或技能，并根据执行反馈持续决策。
4. **无人主动介入的自主修复**：自主发现故障、诊断、选择工具、执行修复并验证结果，逐步探索软件、已登记硬件和未预接入工具的修复能力。

当前先建设监控与控制底座。人机融合、自主修复和外部模型操控仍是后续目标。

## 项目结构

```text
RS/
├── cpp/
│   ├── include/amr/         # 状态类型与公共接口
│   ├── src/                 # 核心规则实现
│   ├── apps/                # 模拟与真机只读入口
│   └── tests/               # C++ 与输出测试
├── web/                     # 仪表盘、回放记录与服务测试
├── tools/
│   └── serve_dashboard.py   # 只读 HTTP 桥接
├── CMakeLists.txt           # 构建与测试入口
├── robot/                   # Jetson 构建、只读启动和查询配置
└── README.md
```

监控链保留 **Jetson C++ → 学校服务器 SSH → PC HTTP → 网页**；SoftAP已搁置，手柄直接接机器人，远程观测经服务器。

PC 是新代码编辑入口；服务器保留旧手部追踪并中转 SSH；电压/里程计/雷达 ROS 采集器已在 Jetson ARM 上编译运行。本轮程序位于机器人用户目录下独立 rs- 项目发布/构建目录，带来源哈希，不设开机自启；不依赖旧 /tmp 验证目录。

## 运行入口

依赖：C++17 编译器、CMake/CTest 3.20+、Python 3.8+。

已配置的 VS Code：

- **Ctrl+Shift+B**：构建并运行 CTest。
- **任务: 运行任务 → RS: 持续模拟仪表盘**：构建并启动网页服务。

已有构建产物时，也可在根目录执行：

```powershell
python tools/serve_dashboard.py
```

打开 [持续模拟仪表盘](http://127.0.0.1:8081/?mode=live)，页面可切换离线回放。Ctrl+C 停止服务；重新编译前先停止运行中的模拟程序。

运行参数、接口与回放说明见 [web/README.md](web/README.md)；离线遥控入口见 [实验台说明](web/teleop/README.md)。VS Code 任务属于个人配置，未随仓库分发。
